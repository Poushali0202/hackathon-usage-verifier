# Stage 1 binding inventory

Per app-development-docs 02 Phase 0: the seven bindings that moved from the
standalone FastAPI + Vite app (`Projects/hackathon-usage-verifier`) into this
shell app. Load-bearing algorithms (deterministic evaluator, target matching,
allowance math) port unchanged; the work is these bindings.

## 1. Shell / API

**Was:** Vite SPA with `react-router-dom`, `frontend/src/api.js` calling a
same-origin FastAPI with an `X-Dev-User` header.

**Now:** One `app:` mount (`src/AppDescriptor.ts`). State-flag navigation
inside `AppLayout`. Data via `useShellConnection()` / `getClient()` — never
`new RocketRideClient()`. Identity via `useAuthUser()`. Sign-in is
`shell:loginRequest`. The `X-Dev-User` header is gone.

Pages: Dashboard, Targets, New run, Quick verify, Runs / run detail, Settings,
Plans.

## 2. Configuration (org vocabulary in code)

**Was:** Hardcoded tenant name, preset product name, closed plan enum in
frontend settings.

**Now:**

- Runtime settings live on the manifest as `contributes.configuration`:
  `hackjudge.judge-hack.graceDays` (integer, default 2) and
  `hackjudge.judge-hack.historyPenalty` (number, default 2). Edited in Settings
  and the shell Settings overlay via `useWorkspace().updateSetting`.
- Plan is not a local enum the user can save; it is derived from
  `useSubscriptions()` (see §7 / billing).
- The RocketRide preset target is a seed row (`ROCKETRIDE_PRESET`) because this
  app's job is to verify RocketRide usage. That name is product vocabulary for
  the judged platform, not leftover publisher branding. Custom targets are
  user data in `appState`. Scoring weights default to the team scale; Company
  and Organizers may persist per-target `weights` / `thresholds`. Extract
  prefill also sets `architecture_template`.

## 3. State / storage

**Was:** Supabase Postgres via SQLAlchemy; browser `localStorage` for
`hj_user`, `hj_theme`, `hj_settings`.

**Now (Stage 1):** Durable UI state is `useWorkspace()`:

| Key | Where | What |
| --- | --- | --- |
| `runs`, `targets` | `appState` | Opaque blob; max 40 runs |
| `hj.theme`, `hj.view`, `hj.runId`, `hj.plan` (fallback) | `usePrefs()` | Per-user prefs, not `localStorage` |
| `hackjudge.judge-hack.graceDays` / `historyPenalty` | workspace settings | Manifest schema |

SQL store, export/import, and retiring any personal DB are **Stage 3**.
`rocketride_sql` is the default. If the signed-in app cannot execute SQL,
runs stay in `appState`. The generator keeps an unused `db_postgres` variant.

## 4. Backend logic

**Was:** 19 FastAPI routes (verify stream, batch, targets CRUD, export,
credentials, health).

**Now:** No app-owned HTTP server.

| Former route | Stage 1 home |
| --- | --- |
| `/api/verify/stream`, `/api/batch` | `src/verify/session.ts` — `tool_python` on the engine + bundled Python evaluator over the GitHub API (judge's token); LLM explain is post-verdict only |
| `/api/targets` CRUD, `/api/runs*` | `rocketride_sql` via `sqlStore` when the broker injects identity; otherwise `appState` via `RunsContext` |
| `/api/targets/test`, `/api/targets/extract` | Same `tool_python` session helpers |
| `/api/export` | Frontend SheetJS (`src/verify/sheet.ts`) |
| `/api/credentials`, `/api/me`, `/api/health` | Shell identity + server-side env |

Deployed `.pipe` files are generated by `tools/gen-pipes.mjs`. Runtime verify
still uses `client.use({ pipeline })` then `client.tool` on `python_1`. Stage 2
adds `validate`, `deploy.add({ deployTo })`, `verifyApp`, `addApp`, and
`publishApp(..., '@me')` via `tools/stage2-publish.mjs`.

## 5. The clock

No cron existed in the source app; runs are user-triggered. `deploy.setSchedule`
is unused. Nothing to migrate.

## 6. Secrets

**Was:** `.env` with `ROCKETRIDE_URI`, `ROCKETRIDE_APIKEY`,
`ROCKETRIDE_ANTHROPIC_KEY`, `ROCKETRIDE_GITHUB_TOKEN`, `DATABASE_URL`.

**Now:** Server-side layered environment only. The bundle never carries a
secret. Runtime names (documented in `.env.example`; owner sets the overlay):

- `ROCKETRIDE_ANTHROPIC_KEY` (org scope; explain pipe)
- `ROCKETRIDE_GITHUB_TOKEN` (**user scope, per judge**; written from Settings → GitHub
  access, read with `account.getEnv('user')` at run start and passed into the
  `tool_python` code — never a shared org secret, never in the bundle)

`DATABASE_URL` is retired. Personal `ROCKETRIDE_HACKJUDGE_PG_*` names exist only
in the unused external pipe placeholders — do not set them. Connection to the
shell is the platform session, not an app-held URI/API key.

## 7. Identity / audit / billing

**Was:** Dev-header stub defaulting to a hardcoded actor; in-app plan preview
saved to `localStorage`; checkout copy said "not wired".

**Now:**

- `authenticated: true`. `useAuthUser()` is required before the app renders.
- Every run create/update and every custom target write is stamped with
  `{ userId, email, displayName }` from `actorFrom(useAuthUser())`.
- Manifest `mode: "subscription"` with three `billing.plans` (Developer $20,
  Company $100, Organizers $200, `interval: "one_time"`, no invented Stripe
  `price_*` ids).
- Checkout emits `shell:subscribe` with the app id only (picker loads live
  prices). Entitlement: subscribed/trialing → nickname/features;
  unsubscribed/canceled/past_due → developer; `free`/`auth`/undefined (prices
  not live) → `hj.plan` pref fallback so the workspace stays usable.
- Company features (`isCompanyPlan`) include Organizers.
